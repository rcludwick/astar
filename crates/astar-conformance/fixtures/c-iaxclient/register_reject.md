# register_reject.pcap (c-iaxclient)

Generated by `harness/asterisk_parity` (iax-7022) using the patched-C
iaxclient against the same Asterisk image as the Rust-side fixtures.
Peer: `astartest:supersecret` (`requirecalltoken=yes` in `iax.conf`).

Flow captured: REGREQ → REGREJ.

## What this proves

libiax2's `iax_register` does **NOT** append an empty `CALLTOKEN` IE on
the outgoing `REGREQ`, even though `iax_call` does. So registration
against a peer with `requirecalltoken=yes` is rejected outright with no
CALLTOKEN handshake. A spec-conformant client would either:
- always opt in with an empty CALLTOKEN IE (matching `iax_call`'s
  behavior), or
- handle the resulting REGREJ + try the CALLTOKEN dance on retry.

libiax2 does neither. The Rust client's FSM-side register implementation
(au:iax-bc14) should treat this as a known divergence from the C ground
truth — sending the empty CALLTOKEN IE on REGREQ is the right thing.

Treat this fixture as a wire-level proof of the gap, not as a behavior
to mirror.
