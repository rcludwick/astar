# register.pcap (c-iaxclient)

Generated by `harness/asterisk_parity` (iax-7022) using the patched-C
iaxclient (snapshot under `c_iaxclient/vendored/` + `c_iaxclient/patches/`)
running in `debian:bookworm-slim` against the same Asterisk image as the
Rust-side fixtures. Peer: `astartest_notok:supersecret`
(`requirecalltoken=no`).

Flow captured: REGREQ → REGAUTH → REGREQ+MD5 → REGACK → REGREL → ACK.

## Companion fixtures and what's deferred

- `register_reject.pcap` — same flow against `astartest`
  (`requirecalltoken=yes`); proves libiax2 does NOT send the empty
  CALLTOKEN IE on REGREQ and gets rejected.
- `incoming.pcap` — register + asterisk-originated inbound call;
  exercises libiax2's NEW-received path.

The four call scenarios (`call_notoken`, `call_token`, `call_ulaw`,
`peer_hangup`) are deferred to au:iax-c308: libiax2's CALLTOKEN-resend
flow resets `peercallno` (via `patches/0001-dcallno-0-on-resent-NEW.patch`)
but does NOT reset oseqno. Against our local strict Asterisk the resent
NEW gets VNAK'd and call setup stalls. Real ASL3 hubs apparently
tolerate this silently, so faithful ground-truth captures need real-hub
access.
